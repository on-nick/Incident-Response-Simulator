Incident Response Simulator

What this is

This tool simulates security incidents, runs them through a rule-based detection engine, and executes an automated response playbook — the same shape of pipeline a real SOC (security operations center) uses, compressed into something you can run and inspect on your own machine.

Scenarios

Port scan
Synthetic events representing sequential probes across common service ports. Flagged once a run touches enough distinct ports to look like reconnaissance rather than normal traffic.
SYN flood (lite)
A short burst of connection-attempt events aimed at one port. Flagged once the burst size crosses a volume threshold, the same way a real IDS would catch an early-stage denial-of-service attempt.
Brute-force login
Repeated failed authentication attempts against a set of common usernames. Flagged once failed attempts cross a threshold — successful logins are never counted.
Malware beacon
Periodic outbound "callback" events, mimicking malware checking in with a command-and-control server. Flagged once enough beacons are observed at a consistent interval.

How detection and response work

Each scenario has its own threshold-based detector — for example, "5 or more distinct ports in one run" for a port scan. Crossing the threshold raises an alert with a severity level, which then triggers a scenario- specific playbook: a fixed sequence of response actions (blocking a source IP, locking an account, isolating a host, and so on) that get logged as executed.

Known limitations

This is a training and portfolio tool, not a production security product. Detection thresholds are simple and static rather than adaptive; response actions are simulated and logged rather than wired into a real firewall, EDR, or identity provider; and the AI-generated incident summary falls back to a template when no API key is configured, so its quality depends on that configuration. Live packet simulation is restricted to loopback and explicitly whitelisted private addresses only.
